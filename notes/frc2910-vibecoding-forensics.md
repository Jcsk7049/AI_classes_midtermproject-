## 一、Vibecoding 機率低的理由

### 1.1 只能來自實體機器的數據（AI 生不出來）

| 位置 | 內容 | 為何不可能是生成的 |
|---|---|---|
| `ReBlitz.java` | CANcoder 偏移 `-0.000244140625`、`0.191650390625`、`-0.1455078125`、`0.32861328125` | 小數第 9 位的實測校正值 |
| `Constants.java` | `HOOD_GEAR_RATIO = (52.0/12.0) * (18.0/12.0) * (146.0/10.0)` | 寫成實際齒數乘積，有人去數齒輪 |
| `ReBlitz.java` | `MAX_SPEED_METERS_PER_SECOND = 4.96`，註明「observed via AdvantageScoped」 | 刻意不用同檔案已算好的理論值 |
| `VisionIOLimelight.java` | `txScalarValue` — 註解記載發現 Limelight `tx` 與 Pigeon 2 偏航角「不以相同比例縮放」，量出比值後修正 | 實驗發現，非生成物 |
| `ShooterInterpolation.java` | 1.3m→2100RPM/0°，5.0m→2900RPM/28° | 實際調校出來的射球表 |

## 二、AI 使用證據

### 2.1 查無的部分

- ❌ 無 `.cursorrules` / `CLAUDE.md` / `AGENTS.md` / `.aider*` / Copilot 設定檔
- ❌ 全文搜尋 `chatgpt|copilot|claude|openai|anthropic|llm|generated by`：**零命中**
- ❌ 122 個檔案**全純 ASCII**，沒有 LLM 常見的 `→` `±` `°` 字元

### 2.2 需要澄清的非證據

單一 `Initial commit`（Jonathan Zimmerman `<tyrius74@gmail.com>`, 2026-06-07）
**不是可疑證據**。FRC 隊伍公開釋出時 squash 掉私有 repo 歷史是標準做法。
代價是 **commit 層級的鑑識完全做不了**，且該作者很可能只是做釋出的人，不是唯一作者。

### 2.3 有訊號的部分：drive stack 是風格離群值

`///` 行內註解 + `Step 1:/Step 2:` 敘事 + ASCII 箭頭（`-->` ×8、`<-->` ×1、`+-2.0`）
**只集中在 4 個檔案**：

- `subsystems/drive/SwerveSubsystem.java`
- `subsystems/drive/SwerveIOCTRE.java`
- `subsystems/drive/SwerveIOSim.java`
- `RobotState.java`

其餘 50+ 個檔案是完全不同的簡練語氣。

### 2.4 「流暢但與程式碼不符」的 javadoc

描述的是程式碼**看起來應該**做什麼，而非實際做什麼：

| 註解宣稱 | 實際情況 |
|---|---|
| `steerRatesRadPerSec` —「模組轉向速率，用於 steer-drive 解耦」 | 宣告後**從未被寫入、從未被讀取** |
| `yawAccelerationRadPerSecPerSec` —「偏航角加速度 rad/s²，用於偵測騰空」 | 存的是 Z 軸**線**加速度 m/s²（`accelerationZ * 9.80665`）；全專案**無任何騰空偵測**；傳進 `RobotState` 後被忽略 |
| `translationErrorMarginForDriveToPoint` —「容差 1.0 inch」 | 實際預設 **6.0 inch**，且欄位初始未賦值 |
| `teleopVelocityCoefficient` —「範圍 0.0–2.0，預設 1.0」 | 是 `private final = 1.0`，**永遠不可能是別的值** |
| `setWantedState` javadoc 列出可用狀態含 `CHOREO_PATH` | enum 裡**沒有這個值** |
| `SwerveSubsystem` 建構子 javadoc 列 4 個參數 | 實際簽章 5 個（漏 `callbackManager`） |
| `TunablePIDController`（整個類別 + 完整 javadoc） | **從未被實例化過** |

這是 LLM 被要求「幫我把這個檔案加上文件」時的典型產物。

### 2.5 相關發現：其他死碼 / 單位問題

（這些不一定與 AI 有關，但在同一輪閱讀中發現，一併記錄）

- `SwerveSubsystem.targetYaw` 是 `final Rotation2d.kZero` → `TRACKING_TARGET` 永遠瞄準 0°，
  其前饋計算恆為 0。該模式未綁定任何操作。
- `SuperStructure.maxVelocityForAuto` 宣告後**從未賦值**（恆 0.0）。兩個讀取點單位還不一致：
  一處包 `Units.feetToMeters()`，另一處沒有。
- `AutoFactory.createTestAuto` 單位重複換算：`Units.feetToMeters(DTP_SLOW_VELOCITY_METERS)`，
  而該常數已是公尺 → 得到約 0.46 m/s 而非 1.52 m/s。
- `FLYWHEEL_RPM_TOLERANCE = 3000.0`，而設定值只有 2100–2900 RPM
  → `isShooterAtTargetRPM()` 實質恆為 true，射擊條件中的 RPM 檢查形同無效。
- PathPlanner 路徑追蹤的三個修正 PID 增益**全為 0** → 若啟用會是純前饋。

## 三、無辜解釋（必須並列）

同一批現象有完全合理的非 AI 解釋：

1. **「被砍掉的功能殘骸」** —— `SwerveIO` 的 inputs 類別看起來就是為打滑偵測 /
   循跡控制預留的欄位。註解在加欄位時寫得有企圖心，功能後來沒做完。
   這在 build season 是**常態**。
2. **ASCII 箭頭可能是隊內規範** —— 為避免 RoboRIO 上的編碼問題而禁用非 ASCII 字元。
3. **`Step 1/2/3` 註解人也會寫** —— 尤其是熱心的學生或在教學導向的檔案裡。
4. **drive stack 風格不同，可能只是不同人寫的** —— 大型隊伍分工，
   drive 通常由資深成員或 mentor 負責。

## 四、結論與建議

**校準後的判斷：**

- 整份 vibecoding：**5–10%**
- drive stack 有過 AI 輔助的文件 / 註解生成：**60–70%**
- 可拿出去當「證明」的東西：**沒有**

**建議：**

- ⛔ 若目的是**公開主張該隊使用 AI** —— 不建議用這些材料。撐不住，
  而且對象是有名有姓的真實隊伍，錯誤指控有實質代價。
- ✅ 若目的是**程式碼鑑識的案例研究** —— 這份材料很好用，正反證據都清楚，
  而且示範了「風格分析」與「證明」之間的距離。

## 附錄：使用的鑑識方法

可重現的檢查步驟：

```bash
# 1. AI 工具設定檔
find . -iname "*.cursorrules*" -o -iname "CLAUDE.md" -o -iname "AGENTS.md" -o -iname ".aider*"

# 2. 關鍵字
grep -rniE "chatgpt|copilot|claude|openai|anthropic|llm|generated by" --include="*.java" .

# 3. 非 ASCII 字元（LLM 常輸出 → ± °）
grep -rPn "[^\x00-\x7F]" --include="*.java" .

# 4. ASCII 化替代符號（被 strip 過的痕跡）
grep -rnP "\-\->|<\-\->|\+\-[0-9]" --include="*.java" .

# 5. 敘事型註解風格
grep -rlP "^\s*///" --include="*.java" .
grep -rnP "Step \d+" --include="*.java" .

# 6. 註解密度（見下方 Python 片段）
# 7. 「文件宣稱 vs 實際使用」交叉比對 —— 對每個有 javadoc 的欄位 grep 其使用點
```

註解密度計算：

```python
import os
for root,_,fs in os.walk('.'):
    for f in fs:
        if not f.endswith('.java'): continue
        p=os.path.join(root,f)
        code=cmt=0; inblk=False
        for l in open(p,encoding='utf-8'):
            s=l.strip()
            if not s: continue
            if inblk:
                cmt+=1
                if '*/' in s: inblk=False
            elif s.startswith('/*'):
                cmt+=1
                if '*/' not in s: inblk=True
            elif s.startswith('//'): cmt+=1
            else: code+=1
        if code+cmt>25:
            print(f"{cmt/(code+cmt)*100:5.1f}%  {p}")
```

**最有效的單一指標：** 第 7 項 —— 交叉比對「javadoc 宣稱的功能」與「該符號的實際使用點」。
人寫的註解會過時，但很少會**憑空描述一個從未被讀寫過的欄位的用途**。
